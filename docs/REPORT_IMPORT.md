# 导入外院报告（图片 → 文字）

外院的化验单、检查报告常常只有手机里的图片，而病历系统在内网电脑上，图片传不进去，只能对着看、手工录入。这个功能解决的是**图片到了内网电脑以后**的事：本机识别成文字，医生对照原图核对，再写进病历草稿。

**图片怎么进内网电脑，由医院认可的通道决定**（摆渡机、网闸、认可的 U 盘等）。产品不提供、也不绕过任何传输通道，不在内网电脑上开放端口。

## 怎么用

1. 把图片通过医院认可的方式放到内网电脑的一个文件夹里；
2. 在听写页面点“更多 → 导入外院报告…”，选择文件夹或图片（JPG、PNG、BMP、WEBP；PDF 和 iPhone 的 HEIC 要先转成 JPG）；
3. 左边是原图（可旋转、放大），右边是识别出的文字：
   - **化验单**：识别出表格，逐项列出“项目、结果、单位、参考区间”，有提示的行（箭头没识别出来、箭头与参考范围不符、结果没识别出来）高亮并写明原因；可以勾选“只写异常项”；
   - **影像报告等文字**：整段识别，按段落合并，去掉手机的状态栏和阅读器工具栏；字形相近、可能认错的字（如“辜丸”对“睾丸”）列在“可能认错的字”里，点选才改；
   - 文字框里可以直接修改；
4. 对照原图核对后，点“写入草稿“辅助检查””。文字加在草稿的“辅助检查”下，标明“外院报告：”，可以撤销。

## 隐私和边界

- 图片只发送给本机服务，只放在内存里：不写磁盘、不写日志、不联网；关闭对话框、开始新的一批、服务停止、闲置 30 分钟都会清除。
- 需要登录；和其他接口一样，只接受来自本程序页面的请求。
- **识别结果只是草稿。** 页面不会自动写入、不会自动提交。识别错误很可能出在最重要的地方（数字、单位、箭头、不常见的医学术语），而识别器给出的“把握”不能用来判断哪里错了（错字的把握常常也在 0.9 以上），所以每一项都要医生对照原图核对。
- 手机拍摄、保存、传递患者报告属于个人信息处理，医院要有规定；本功能不替医院做合规判断。

## 它做了哪些补救，没做什么

- 化验单的**上下箭头经常丢**（红色的尤其如此）：根据结果和参考区间重新判断，与图片上的箭头不一致时提示；结果在区间内但图片上有箭头，也提示。**区间本身识别错了就没法判断**，这时以图片上的箭头为准。
- 上标丢失（“10^9/L”读成“109/L”）：只在单位一列修复。
- **没有结果的行不会被补上**，会提示“没有识别出结果”。
- 字形相近建议只针对影像和检查报告的文字，用的是 `server/data/reference/imaging_terms.txt`（项目整理的草稿词表，待医生审核）、药名和已发布词库。化验单的项目名称不做这个检查。
- 还没做：PDF、HEIC、化验单以外的表格（如心电图测量值表）、手写、拍摄时歪斜反光的校正。

## 识别效果（只在两个样本上看过，不是准确率结论）

- 用 3 张手机截图（2 张 CT 报告文字，1 张血常规）试过：化验表格的 28 行都正确分行分列，3 个丢失的箭头靠参考区间找了回来；CT 报告文字大部分一字不差，但“睾丸、鞘膜、紊乱、颏下、肾盂”这类字形相近的医学术语出现了错误，已列入建议。
- 纸质报告用手机拍摄（歪斜、反光、阴影）没有测过，效果会更差。
- 要得到可信的准确率，需要几十张真实图片和医生核对过的文字。

## 技术说明

- 识别引擎：RapidOCR（onnxruntime，CPU）加 PP-OCRv4 中文轻量模型；OpenCV 用 headless 版，打包时删除不用的视频组件。依赖由 `scripts/build_package_venv.ps1` 安装。
- 代码：`server/report_api.py`（接口和内存会话）、`server/report_ocr/`（`engine.py` 识别、`layout.py` 去手机界面和合并段落、`lab_table.py` 化验表格、`similar.py` 字形相近建议）；页面 `extension/report.js`、`extension/report_logic.js`。
- 测试：`tests/test_report_import.py`（接口、化验表格、字形建议，用合成数据；装有识别组件和中文字体时还会用真实引擎读一张画出来的图）、`tests/test_report_page.py`、`tests/js/report_logic.test.js`。真实患者图片不放进仓库（`samples/` 已被 git 忽略）。
- 安装包体积：识别组件压缩后约 66 MB（实测，见对话记录；最终以构建结果为准）。
