# 从本院病历提取热词（网页里的功能）

医院自己的病历里有大量本科室常用的药名、检查名、缩写。听写页面的“热词”页有一个按钮 **“从本院病历提取热词…”**，打开后可以在网页里完成：选病例 → 分析 → 勾选 → 生成词库。不需要命令行，也不需要 Excel。

**病例不出这台电脑，也不联网。** 病例只发送给本机的语音服务（127.0.0.1），只放在内存里，关闭窗口即清除，上传和分析过程中不写磁盘（服务把上传文件的内存缓冲上限调高到 64 MB，单次上传不会落到临时文件）、不写日志；返回给页面的只有词和统计数字，生成的词库里只有词。

## 怎么用

只有**管理员**账号能用这个功能（见 `docs/LOCAL_ACCOUNTS.md`）。在听写页面右侧打开 **热词** 页，点 **从本院病历提取热词…**。

1. **选择病例**：选一个文件夹（包括子文件夹），或选若干文件。支持 `.txt`（UTF-8 或 GBK）和 `.docx`。旧版 `.doc` 不支持，页面会提示请在 Word 里另存为 `.docx`。默认**一个文件是一份病例**。一个文件里放了多份病例时，在“高级选项”里填每份病例开头的文字（如“姓名”）。
2. **分析**：设“每个词至少出现在多少份不同病例里”（默认 5，不能低于 3），点“开始分析”。病例多时需要几十秒到几分钟。
3. **勾选**：表里列出候选词，有病例数、主要出现在哪个小标题下、类型、日常词频。可以搜索，可以“隐藏日常用语”，可以“选中当前显示的”。**优先选识别经常出错的词**（药名、检查名、缩写、本地说法）；“患者”“病史”这类日常用语识别本来就对，不必选。
4. **生成词库**：选专业、起名称，点“生成词库”。
   - 审核医生一栏留空：生成的是**草稿**，默认不启用。医生在“热词”页勾选“试用尚未经医生审核的专业词库”才会用到；
   - 填了审核医生姓名：登记为已审核，**默认启用**。请只在医生核对过词表之后填写。
   - 生成的两个文件（`hospital_<…>.txt` 和 `.manifest.json`）放在安装目录的 `server\data\hotword_packs\`，同名再次生成会覆盖；删除请用该文件夹里的文件，或调用 `POST /hotword-miner/packs/delete`（只能删除本功能生成的 `hospital_` 开头的词库）。

要把词库带到另一台电脑，把这两个文件复制到那台电脑的同一文件夹，重启服务即可。带出之前请先通读一遍 `.txt`。

## 隐私保护做了什么

1. **只返回词**，不返回句子、不返回上下文；病例文本只在服务的内存里，处理完分析后不写任何地方；关闭对话框、新上传一批病例、服务停止、闲置 30 分钟都会清除。
2. **门槛**：一个词必须出现在不少于 N 份**不同**病例里才会列出，默认 N=5，页面不允许低于 3。只在个别病例里出现的词（罕见病、手术组合、地名、特殊说法）不会出现。
3. **去标识化**：数字、日期、身份证号、手机号、座机、邮箱、网址不会成为词；“姓名：”“患者”“医生”“主治医师”等后面的姓名会从全部病例中收集、移除，并禁止出现在结果里（页面只显示去除了多少个，不显示姓名）；疑似人名、地名、机构名的候选被剔除；字母缩写中带长数字的（病案号之类）被剔除。
4. 生成词库时，只接受**本次分析结果里出现过**的词，并再次检查：像证件号、电话、编号的词会被拒绝。
5. 这些接口和所有改动数据的请求一样，要求请求来自本扩展（见 `docs/LOCAL_SERVICE_SECURITY.md`）。

**这些措施不是万无一失。** 例如：同一位患者有 5 份以上的记录，且某个罕见词只与他有关，就可能过门槛；姓名没有写在上述标签之后时识别不到。因此：

- N 的取值请与医院信息科/伦理确认，建议不低于 5；
- **医生勾选前必须逐条看过候选词**；
- 把词库带出内网之前，请再通读一遍 `.txt`。

## 它能做什么、不能做什么

- 词频高**不等于**语音识别会听错。很多高频词识别本来就对，放进热词反而占名额。热词总数有上限（均衡档约 320 个，所有词库合计），页面在勾选超过 300 个时会提醒。
- 病历是书面语，医生口述时可能说法不同（如写“CT”，说“C T”或“胸部平扫”）。词库里应是医生**口述**时会说出来的词。
- 词是统计出来的，没有词典：新药名、本地用语能找到，但也会有“就诊”“既往有”这类日常搭配混进来，需要医生剔除。
- 一个词只出现在固定的上下文里（例如永远是“考虑XX，予…”），统计上分不清它是词还是短语，会被当成片段而漏掉。
- 阈值（内聚度 3.0、边界熵 0.5、日常用语 1000）是在合成病例上定的初始值，**没有用真实病例调过**。第一次在真实病例上使用后，请看候选表的质量，再决定是否调整（接口 `POST /hotword-miner/scan` 有对应参数）。
- 字母缩写按出现的病例数列出，不做内聚度检验；大小写合并，显示最常见的写法。
- 对话框目前只有中文界面。

## 接口（给开发者）

都是 `POST`，都要求来自扩展的 Origin。

| 接口 | 作用 |
|---|---|
| `/hotword-miner/upload` | 分批上传病例文件（multipart，每批不超过 200 个文件 / 64 MB；首批不带 `session`，返回的 `session` 用于后续批次）；总量不超过 800 MB |
| `/hotword-miner/scan` | `{session, min_cases, case_start, min_pmi, min_entropy, common_freq, top}` → 候选词和统计 |
| `/hotword-miner/build` | `{session, words, specialty, label, reviewers, pack_id}` → 写词库 |
| `/hotword-miner/clear` | `{session}` 立即清除内存中的病例 |
| `/hotword-miner/packs/delete` | `{pack_id}` 删除本功能生成的词库 |

代码：`server/miner_api.py`（接口）、`server/hotword_miner/`（读取、去标识化、统计、写词库）、`extension/miner.js` 和 `extension/miner_logic.js`（对话框）。

## 测试

`tests/test_hotword_miner.py`（接口全流程）和 `tests/js/miner_logic.test.js`（对话框里不依赖页面的逻辑）用合成病例（含虚构姓名、电话、身份证号）检查：常见词被找到、门槛以下的词不出现、任何姓名/号码/地名不出现在返回里、返回里没有病例原文、上传和分析不写磁盘、会话过期/清除后无法再用、勾选后生成的词库默认是草稿且不会被启用、外来网页不能调用任何一个接口。仓库里没有、也不应该放任何真实病例。

**对话框本身（点击、勾选、进度条）没有自动化的浏览器测试**：按约定测试不启动任何浏览器。页面代码做过语法检查和上面的逻辑测试，实际点击效果需要在浏览器里手工确认一次。
