# 本机账号与登录（多位医生共用一台电脑）

医院电脑通常由多位医生轮流使用。插件现在需要先登录；每位医生的草稿和设置互相独立。账号只保存在这台电脑上，不对接医院的任何系统，不联网。

## 怎么用

- **第一次使用**：打开听写页面，会要求设置管理员账号（用户名、密码）。之后由管理员在页面右上角的“账号管理”里为每位医生添加账号。
- **日常**：登录后使用。**用完点“退出登录”**（会清除您保存的草稿）；**暂时离开点“锁定”**（保留草稿，回来重新登录即可继续）。
- **自动锁定**：10 分钟没有操作（听写时不算闲置）会自动锁定，并清空屏幕。
- **一次只有一位医生登录**：下一位医生登录时，上一位的登录自动结束（他保存的草稿仍在，用他的密码登录后恢复）。
- **忘记密码**：请管理员在“账号管理”里重置。重置后，该医生此前保存的草稿无法恢复，会被删除（见下）。
- **修改密码**：页面右上角“修改密码”，保存的草稿会跟着换密钥，不丢。

## 保存的草稿

为了防止电脑意外重启、页面被误关而丢失正在写的内容，草稿、版本记录和患者标签会**自动保存，默认 12 小时后自动删除**（可在“热词”页旁的开关里关闭自动保存）。

- 保存在这台电脑上的服务数据目录里（`%LOCALAPPDATA%\BingliAssistant\users\<编号>\workspace.bin`），**不保存在浏览器里**；
- 用该医生的密码派生出的密钥加密（AES-256-GCM）。密钥只在他登录期间存在于服务的内存里，不写磁盘；**别的医生即使拿到这个文件也无法读取**；
- 到时间会被删除（任何医生登录时都会清理所有过期文件）；点“退出登录”会立即删除；
- 管理员重置密码、删除账号时，对应的草稿一并删除；
- 录音从不保存。

## 每位医生独立的内容

| 内容 | 位置 |
|---|---|
| 草稿、版本记录、患者标签 | 服务端，加密，限时 |
| 自定义热词 | 每位医生一份（`users\<编号>\hotwords.txt`） |
| 界面语言、识别模式、专业选择、自定义模板等设置 | 浏览器里，按医生分开存放 |
| 反馈 | 记录提交者的用户名；导出反馈仅管理员 |

## 角色

- **医生**：听写、自己的热词和设置、提交反馈。
- **管理员**：另外可以管理账号、使用“从本院病历提取热词”、导出反馈、查看登录记录。至少要保留一位可用的管理员。

“停止服务”按钮（以及托盘和开始菜单里的停止）不需要登录，因为它要在没人登录时也能用；它仍然只接受本机、来自本扩展或启动器的请求。

## 安全设计

- 密码用 scrypt 加盐哈希后保存，从不记录、不明文保存；日志和登录记录里没有密码和内容。
- 连续输错 5 次会被锁一段时间（30 秒起，逐次加倍，最长 15 分钟）；用户名不存在、密码错误、账号停用时提示完全相同。
- 登录后得到一个随机令牌，只保存在浏览器扩展的会话存储里（关闭浏览器即消失，其他网页和扩展读不到）。除登录、状态检查、健康检查和停止服务外，所有接口都必须带令牌；WebSocket 把令牌放在子协议里，不放在网址里（网址会进日志）。
- 上述接口和原有的来源校验叠加：外来网页即使拿到令牌也会被拒绝。
- 登录记录（`audit.log`）只记谁、何时、成功与否。

## 它不能保证什么

- **这不是抵御操作系统层面访问的屏障。** 如果多位医生共用同一个 Windows 登录，能操作这个 Windows 账户的人可以删除账号文件重新设置，或者读取浏览器配置目录里的非草稿内容（设置、模板）。删除账号文件不会让别人读到已加密的草稿（密钥来自密码），但会让它们永远打不开。要真正隔离，请让每位医生使用自己的 Windows 账户。
- 能在医生登录期间读取服务进程内存的程序（本机恶意软件）可以拿到密钥和令牌。
- 剪贴板：点“复制”之后，内容在剪贴板里，下一位医生可能粘贴到它。登录页不会清剪贴板。
- 若一位医生忘记退出也不锁定，下一位医生登录前，屏幕上仍是上一位的内容：请养成用完退出或锁定的习惯。自动锁定只在闲置 10 分钟后发生。

## 配置（环境变量，一般不需要改）

| 变量 | 默认 | 说明 |
|---|---|---|
| `BINGLI_IDLE_MINUTES` | 10 | 闲置多久自动锁定 |
| `BINGLI_WORKSPACE_HOURS` | 12 | 保存的草稿保留多久 |
| `BINGLI_SESSION_MAX_HOURS` | 12 | 一次登录最长有效时间 |
| `BINGLI_HOME` | `%LOCALAPPDATA%\BingliAssistant` | 账号和保存内容的位置 |
| `BINGLI_AUTH` | 1 | 设为 0 关闭登录，**仅用于开发和测试** |

## 升级说明

- 升级到带登录的版本时，浏览器里原来**未加密**保存的草稿和患者标签，会在第一位登录的医生登录时移入他的加密保存区，并从浏览器里删除。
- 原来的设置（语言、专业等）会作为每位医生的起点，之后各自独立。
- 原来共用的“自定义热词”不会自动分配给任何人（原文件保留在 `server\data\hotword_packs\user_custom.txt`，需要的医生可手工导入）。

代码：`server/accounts.py`（账号、会话、加密保存）、`server/auth_api.py`（接口和拦截）、`extension/auth.js`（登录页面）。测试：`tests/test_auth.py`、`tests/test_auth_page.py`、`tests/js/auth_logic.test.js`。登录界面本身（点击、输入）没有自动化的浏览器测试，需要手工确认。
