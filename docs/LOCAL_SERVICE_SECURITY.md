# 本机服务的访问控制

本文说明本地语音服务（`127.0.0.1:8765`）允许谁访问、怎么防止医生电脑上打开的其他网页滥用它，以及还剩哪些风险。实现在 `server/security.py`。

## 要防的问题

服务只监听本机，但医生的浏览器里同时开着的**任何网页**都能向 `127.0.0.1:8765` 发请求：

| 手段 | 浏览器自带的跨域限制管不管 | 后果（没有来源校验时） |
|---|---|---|
| 发送 POST（如 `text/plain` 的 JSON、表单上传） | 只阻止读取回复，**请求照样发出** | 往热词库写入、往反馈文件写入、占用识别 |
| WebSocket 连接 | **完全不管** | 任何网页可以连上识别服务 |
| DNS 重绑定（陌生域名临时指向 127.0.0.1） | 浏览器认为是同源，**不拦** | 网页可以读到反馈内容、诊断信息等 |

测试中用真实 Edge 演示过：去掉校验时，陌生网页成功打开了 WebSocket，POST 被服务正常处理，重绑定的主机名拿到 200。

## 现在的规则

每个 HTTP 请求和 WebSocket 握手在到达任何接口之前，先检查：

1. **客户端必须是本机**；
2. **Host 头必须是本机名称**（`127.0.0.1`、`localhost`、`[::1]`），陌生域名一律拒绝，这一条挡住 DNS 重绑定；
3. **如果带了 Origin，必须是浏览器扩展或服务自己的状态页**，否则拒绝（返回 403，且不带任何跨域许可头）；
4. **会改动数据的请求（POST、PUT、DELETE 等）和所有 WebSocket 必须带上述合法 Origin。**浏览器对这类请求一定会带 Origin，网页无法伪造；
5. 不带 Origin 的普通读取（GET）允许：在地址栏打开 `/health`、托盘启动器、命令行脚本都是这种。**浏览器扩展自己发出的 GET 也不带 Origin**（用真实 Edge 实测确认过，POST 才带），所以读取请求无法按扩展 ID 区分；
6. 但如果浏览器声明请求来自别的站点（`Sec-Fetch-Site: cross-site` 或 `same-site`，例如陌生网页里的 `<img>`、`<script>` 标签），即使不带 Origin 也拒绝。扩展、地址栏、启动器是 `none`，服务自己的页面是 `same-origin`，都不受影响。

`POST /service/shutdown`（停止服务）在此之外还要求自定义请求头 `X-Bingli-Control: 1`。

被拒绝的请求会写入服务日志（`service.log`），带上来源和原因，方便排查。

覆盖范围由测试保证：`tests/test_security.py` 会遍历应用里**所有路由**，用陌生来源逐个请求，新增接口会自动被覆盖。

## 固定扩展 ID（默认已启用）

扩展的 `manifest.json` 里带有 `key` 字段，所以无论从哪个目录加载，扩展 ID 都固定为同一个（由 `scripts/extension_id.py` 从 `key` 算出）。服务默认只放行 `server/data/allowed_extensions.json` 中列出的 ID，其他浏览器扩展不能写入、也不能使用识别。

- 签名私钥（打包上架用）保存在仓库之外（用户目录下的 `.bingli` 文件夹，文件名 `extension_key.pem`），`*.pem` 已被 git 忽略；`key` 里只有公钥。
- 换 ID 后，浏览器把它当成另一个扩展：**以前用路径方式加载的版本里保存的本地草稿和设置不会带过来**。第一次升级到固定 ID 的版本时需要提醒医生。
- 预期的 ID 可以在 `edge://extensions`（只读查看）中核对，应与 `allowed_extensions.json` 一致。从 `key` 推算 ID 的方法没有在浏览器里验证过，第一次安装时请核对。
- 临时放开或改用其他 ID：用环境变量覆盖，`*` 表示不限制。

**它能限制的范围**：会改动数据的请求（POST、PUT 等）和 WebSocket。**限制不了读取**：扩展发出的 GET 不带 Origin（见上），服务无法分辨是哪个扩展发的。所以其他扩展仍可能读到热词、反馈、诊断信息这类数据，但不能写入、不能使用识别。

```
set BINGLI_ALLOWED_EXTENSIONS=<扩展ID>[,<扩展ID>...]
```

`BINGLI_ALLOWED_EXTENSIONS` 设置后，替代 `allowed_extensions.json` 中的列表。

## 病例提取热词的接口

“从本院病历提取热词”会把医生选的病例文件发给本机服务（`/hotword-miner/*`）。这些接口都是 POST，和其他改动数据的请求一样，必须带本扩展的 Origin，外来网页会被拒绝（`tests/test_hotword_miner.py` 逐个接口验证）。病例只放在服务的内存里，不写磁盘、不写日志，关闭对话框、闲置 30 分钟或服务停止即清除；返回的只有词和统计。详见 `server/hotword_miner/README.md`。

注意：本机上的其他程序仍然可以绕过浏览器直接调用这些接口（见下），所以这个功能适合在医生本人使用的电脑上用。

## 没有解决的

- **本机上的其他程序**可以伪造 Origin 头直接访问服务；登录之后，它们没有令牌就只能访问登录页、健康检查、状态和停止服务这几个入口。本地服务无法防御已经在本机运行并能读取其他进程内存的恶意程序；
- **其他浏览器扩展**：能读取（固定扩展 ID 也挡不住，见上），但不能写入和使用识别；
- 登录令牌只存在浏览器扩展的会话存储里，**本机上不经过浏览器的程序拿不到令牌**，所以它们无法调用需要登录的接口；但能读取浏览器或服务进程内存的恶意软件仍可能拿到（见 `docs/LOCAL_ACCOUNTS.md`）；
- 反馈文件、热词文件是本机明文文件，权限取决于电脑的用户账号；
- 服务未做访问频率限制：本机的合法扩展可以连续提交请求。

## 对开发和排查的影响

- 命令行用 `curl` 发 POST 需要自己带头：`curl -X POST -H "Origin: http://127.0.0.1:8765" ...`；
- 测试里的 `TestClient` 需要设置 `headers={"Origin": "http://testserver"}`；
- 启动器和 `scripts/service_ctl.ps1` 发停止请求时已经带上合法的 Origin 和控制头；
- `GET /health`、`/service/status`、状态页 `/` 仍可直接在浏览器地址栏打开。
